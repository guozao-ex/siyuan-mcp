# 思源 MCP 项目规格说明

## 项目概述

**项目名称**: 思源 MCP (SiYuan MCP)

**项目目标**: 开发一个通用的思源笔记 MCP 服务器和配套插件，支持所有 MCP 协议的 AI Agent 与思源笔记进行交互。

**交付物**:
1. MCP 服务器：提供标准 MCP 协议接口
2. 思源插件：提供用户友好的 UI 交互界面

## 核心功能规格

### 1. MCP 服务器

**职责**: 作为 AI Agent 和思源笔记之间的桥梁，提供标准化的 MCP 工具。

**核心工具**:
- `search_notes`: 搜索笔记和块
- `read_note`: 读取笔记内容
- `create_note`: 创建新笔记
- `update_note`: 更新笔记内容
- `list_notebooks`: 列出笔记本

**技术要求**:
- 支持 stdio 和 HTTP 两种传输模式
- 兼容 @modelcontextprotocol/sdk v1.x
- 提供完整的错误处理和日志记录

### 2. 思源插件

**职责**: 在思源笔记内提供 AI 功能的可视化界面。

**核心功能**:
- AI 对话面板：与 AI 进行自然语言对话
- 块级操作：右键菜单提供总结、续写、改进功能
- 配置管理：设置 MCP 服务器地址和认证信息
- 国际化：支持中文和英文

**技术要求**:
- 使用 Svelte 4 构建 UI
- 通过 Vite 构建，符合思源插件规范
- 兼容思源笔记 >= 2.9.0

## 非功能需求

### 性能
- MCP 工具响应时间 < 2 秒（常规操作）
- 插件 UI 渲染流畅，无明显卡顿
- 支持处理大文档（> 100KB）

### 安全
- API Token 安全存储
- 不在日志中泄露敏感信息
- 遵循思源笔记安全最佳实践

### 可维护性
- 代码覆盖率 > 70%（Phase 5）
- 完整的 TypeScript 类型定义
- 清晰的文档和示例

### 兼容性
- 支持 Windows, macOS, Linux
- 兼容主流 AI Agent（Claude Desktop, Cline, Continue 等）
- 向后兼容思源笔记 API

## 项目约束

### 依赖约束
- 最小化外部依赖，优先使用标准库
- 所有依赖必须有明确的版本锁定
- 避免使用不稳定的 API

### 架构约束
- Monorepo 结构，两个独立子项目
- 服务器和插件可独立部署和使用
- 清晰的模块边界和职责分离

### 开发约束
- 遵循 Comet Native 工作流
- 每个 Phase 完成后提交并推送
- 保持文档与代码同步更新

## 风险和挑战

### 技术风险
- **MCP SDK 不稳定**: 当前版本较新，可能存在 breaking changes
  - 缓解措施：锁定版本，关注官方更新
- **思源 API 变更**: 思源 API 可能在版本更新中变化
  - 缓解措施：使用稳定的 API，做好版本兼容

### 集成风险
- **跨进程通信**: 插件与 MCP 服务器通信可能存在延迟
  - 缓解措施：实现超时和重试机制
- **权限问题**: 本地文件访问可能受限
  - 缓解措施：提供清晰的权限说明
